Answer written questions 1 and 2 here.
1. SFML's coordinate system has the positive y-axis point down, which I believe makes it so that angle calculations require an angle offset (based on what GameState's update() function comments say).
This surprised me considering that I didn't expect an offset to be needed at all.

2. I think the benefit of this design is separation of concerns, i.e with this design processInputs literally only has to deal with inputs and gameState's update function only has to deal with updating its state based on what the current input is.
